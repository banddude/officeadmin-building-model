# Bounded preliminary circuit proposals

`oabm.proposals.circuit_design` adds the AI task `propose_preliminary_circuit_groups`. It starts from source-verified placement intake and proposes selections among caller-supplied choices. It cannot create canonical objects, replace observed circuiting, choose arbitrary physical parameters, approve its own output, or certify engineering/code compliance. The source and design gates remain deterministic. No provider SDK, credentials, network client or live inference is installed by this module.

## Request and context

`CircuitProposalRequest.capture(model, review, placement=..., policy=..., review_policy=..., source_port_ids=..., connectors=..., profiles=..., images=..., contexts=...)` replays the existing `materialize_asserted_symbols` input set to derive eligible devices and the admitted snapshot. `placement` has exactly the existing runs/documents/images/journal_paths/decisions/registrations/assertion_review/evidence_documents keys. All admitted electrical devices in that source review are eligible; upstream deferred/pending proposals remain explicit missing placements.

The request binds original base, admitted model, symbol and assertion reviews, routing/review policies, source proposals and canonical owner snapshots. Context includes all model entities on selected device/panel levels and unlevelled entities, preserving unknowns, owner-relative provenance and canonical units. It is capped at 512 snapshots and 128 eligible devices; exceeding a bound requires explicit partitioning rather than silently discarding context. No GLB display thickness becomes canonical geometry.

`CircuitImage` reuses SourceImage render manifests and pixel verification with task-specific context roles. Plan, legend, fixture schedule, panel schedule, notes, one-line, riser, detail and project rules each require supplied/missing/inapplicable status and rationale. Every image must be enumerated under its actual role; project rules enumerate every supplied profile. Supplied plan images must cover each eligible mark on its exact original PDF/source page. Grouped device plan citations must cover that mark. Context availability is a caller declaration, not evidence that every relevant project document has been discovered. Normalized crop citations remain inferred interpretations, not verified OCR facts.

## Approved choices and transport

`ApprovedCircuitProfile` requires every CircuitDesignRules and RoutingOptions field, nonempty RuleReferences and project-decision approval evidence. `ApprovedConnector` requires an eligible proposal ID, finite canonical-frame offset and nonzero direction, basis and approval evidence. Source choices name existing canonical panelboard electrical source ports with known levels. Unknown facts are represented by absent choices and structured `MissingInput` rows, never prototype defaults.

`CircuitReviewPolicy.capture` binds the exact source-port, connector and profile choice set plus authorized reviewer identities. Dispatch and compilation compare those choices against that independent caller policy and verify actual approval/authorization bytes. A request cannot substitute another profile while keeping an old approval digest. Configurations/authorizations are trusted application inputs; this library does not authenticate their origin.

`CircuitRoutingPolicy` uses existing RoutingConfig endpoints. The strong baseline is vision_sol. Diagnostic Astra requires explicit mode and cannot compile into reviewed design. No cheaper qualification is inherited, and no automatic availability fallback/model substitution occurs. Missing transport-reported model identity stays unknown when explicitly permitted; a configured expected identity must match.

`dispatch_circuit_proposal` accepts injected callables with the existing provider/model/prompt-version kwargs and immutable image bytes. The first argument is `{request, transport}`. Transport contains the new task-specific prompt/schema, version and their hashes. It does not use the symbol prompt or SymbolOutput. AttemptJournal/AttemptReceipt durability and strict raw metadata budgets are reused. Each receipt binds the full execution-envelope fingerprint, including prompt/schema, and the configured endpoint. Requested alias and transport-reported identity are separate. Start is fsynced before the call; no successful run is returned if finish cannot be persisted. Raw output is retained without coercion or repair.

## Pending output and trusted review

`CircuitProposalOutput` selects only supplied IDs, explicitly accounts for every eligible device as grouped/deferred/excluded, and exactly covers grouped devices once. It preserves all mandatory missing-input rows and may add unknowns. The one-profile first slice is homogeneous; unsupported mixed physical requirements require another explicit scope. It emits no route coordinates, engineering facts, review actor or acceptance state. CircuitProposalRun remains accepted=false/review_state=pending with inferred provenance.

`CircuitReviewDecision.capture` binds the exact run, original request/output, independent review policy, actor and full reviewed selection. Explicit edits may choose differently among the authorized candidates or defer/exclude devices. They cannot invent choices or erase missing facts without recapturing new evidence. `compile_circuit_review` verifies the actual execution journal, current placement/source pixels, model/review/choice fingerprints, approved evidence and actor policy before constructing ReviewedCircuitRequest.

Review authority may be caller-declared human or a configured agent with an `agent:` identity, exact configuration fingerprint and authorization document. Agent review records human_confirmation=false and is never labeled as the owner's personal confirmation. The existing canonical user derivation denotes an explicit caller-authorized design instruction, not proof that a human authored it. Actor kind, configuration, authorization, AI inferred provenance, original output, reviewed edits, selected profile/connector fingerprints and unresolved inputs remain in the hash-bound decision evidence. Applications must enforce their review authorization outside model output.

The compiler returns the existing request, decision bytes, evidence-document mapping and structured missing inputs. Stable load-port IDs use canonical device IDs, not transient proposal execution IDs. Pass the request/evidence to the existing reviewed electrical or saved entrypoint. Retained source/evidence and generated project artifacts must stay private for real jobs. The merged saved-revision verifier replays the resulting placement and circuit graphs and preserves the full request lineage; it does not authenticate an AI receipt or review actor. A journal hash chain establishes internal binding and durability, not a provider signature.

## Acceptance and limits

CI uses fake injected adapters and independently drawn synthetic floor/legend/schedule inputs. Acceptance covers two admitted marks and one upstream deferred placement, explicit non-default profile, pending AI output, authorized configured-agent review, actual saved CLI delivery, deterministic repeat, IFC provenance, reviewed-height recomputation, stable logical IDs and exact saved revision diff. Negatives cover stale/mutated inputs, source page/pixels, unsupported choices, incomplete/malformed profiles, omitted/duplicate dispositions, citation bounds/pages, missing unknowns, self-approval/identity claims, unauthorized/stale review, explicit edits, journal failures and unavailable endpoints.

A legend cannot supply an unseen connector, mounting height, load or panel capacity. New grouping is designed intent even when source circuits are absent. Capacity, load calculation, sizing adequacy, fill, protection, supports, installability, jurisdiction/edition verification, compliance and source completeness remain unresolved. Existing circuitry requires reconciliation; missing equipment is not silently placed through the legacy prototype path. No live model quality, production readiness or permit acceptance is claimed.


A circuit dispatch requires a newly created, empty attempt journal. Both durable records and in-memory receipts are checked, and a one-shot in-process reservation prevents concurrent calls from claiming the same journal before the first durable start. Reuse after either success or failure is rejected before transport, preserving prior run compilability. A retry uses a new journal and retains the original attempt; reopening or appending a second execution is not a recovery mechanism.

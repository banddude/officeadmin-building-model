# Circuit sizing provider boundary

This opt-in boundary lets a caller give a validated canonical circuit and explicit design inputs to an in-process provider. It returns a source-bound **proposal**, never mutates the model, and never authorizes construction or represents code compliance. No provider, network connection, credential, or OfficeAdmin integration is included or enabled by default.

`single_route_length_ft(model, circuit_id)` supports only one legacy polyline directly connecting one source and one load. It returns one-way geometric centerline length and route ID. It does not add terminations, slack, installation allowances, or choose a route. Multiple loads, multiple routes, and physical-route geometry are refused.

`size_model_circuit(model, circuit_id, design_inputs, provider)` captures a detached validated model, reconciles supplied circuit voltage, load, poles and phase, and checks explicit route references and shared-route evidence. It passes a copied request to the caller-selected callable. The request includes version, purpose, model/circuit identifiers, model hash, request digest, explicit assumptions and source/route provenance. The returned proposal echoes these fields; mismatched bindings, fabricated target mappings, and sizes in non-partial responses are refused.

The sizing input schema requires explicit topology, load, materials, insulation, location, ambient/termination temperatures, ground and neutral details, raceway occupancy and length basis. Missing facts are returned as unresolved without calling a provider. This bounded version supports dry locations, one circuit per raceway and one conductor set. It refuses one-hot circuits without a neutral, split-phase two-hot circuits with a neutral, and unbalanced three-phase inputs. A three-phase request requires an explicit balanced-load assertion. Insulation and temperature inputs are conservatively bounded. A provider may report unsupported or unresolved cases. The consumer appends its own unverified-proposal warning to every provider response.

The result maps proposed wire and conduit sizes to the circuit and route IDs and preserves existing conductor facts. It explicitly records `applied: false`; ground size is not verified. The provider reports its own name and version; this identity is not independently authenticated. Different overlapping route IDs, unmodeled raceway contents, source fact correctness, code edition, overcurrent protection, ground adequacy, termination/slack allowances and physical installation remain outside the boundary. Centerline-derived length is geometry only and does not include allowances. It is not a complete engineering or takeoff workflow.

The schemas in `contracts/` are mirrored as package resources and verified for parity in the tests. Providers are supplied by the caller, which is responsible for deciding whether to disclose model data to the chosen provider and for validating its calculations. The request digest correlates request and result; it is not a signature or authentication.

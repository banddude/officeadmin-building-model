# Source coverage CLI

This optional offline tool makes the existing source-coverage accounting API usable with a manually supplied takeoff. It reads a canonical model JSON, a nonempty JSON array of source-item IDs, and the source file to which those IDs refer. It hashes the source file's exact bytes; it does not parse the source, extract IDs, or verify that the ID list is complete.

1. Run `oabm-source-coverage prepare --model MODEL.json --source SOURCE --inventory IDS.json` and save the JSON mapping template locally. It binds the manually supplied inventory to the source-byte hash and the normalized model fingerprint.
2. A reviewer adds entries to the mapping template: `{"source_id":"ID","canonical_ids":["canonical:id"]}` or `{"source_id":"ID","omission_reason":"reason"}`. Missing IDs remain unresolved. Never silently regenerate a mapping after inputs change; review the changes and prepare a new mapping.
3. Run `oabm-source-coverage audit --model MODEL.json --source SOURCE --inventory IDS.json --mapping MAPPING.json`. Optional `--strict` rejects unresolved inventoried IDs, but explicit omissions are permitted; it does not mean every source item was modeled.

Output goes only to stdout. The user chooses whether and where to save it, and should treat source IDs, model data and omission reasons as private. Redirect only to a separate file: your shell can truncate an input file before the tool starts. No upload, network connection, source extraction, code-compliance determination, quantity check or design approval occurs. A mapped row only confirms that referenced IDs exist: the tool does not verify entity type, quantity, location, circuiting, or whether multiple source IDs refer to the same entity. Audit output labels these limitations explicitly; strict mode does not prove the input inventory itself was complete. Files must be nonempty regular files; source files are limited to 256 MiB and JSON inputs to 32 MiB. A run supports at most 2,000 source IDs and 10,000 total mapped target references. On platforms supporting `O_NOFOLLOW`, input symlinks are refused. The hash is a correlation value, not authentication, and files can change after the report is produced.

Schema validity alone does not prove freshness, unique source IDs, mapping truth or authenticity. Rerun the audit with the current model, source and reviewed mapping before relying on a saved report.

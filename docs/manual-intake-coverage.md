# Reconcile manual intake with source coverage

`reconcile_manual_intake(base, intake_request=..., source_path=..., strict=False)` connects the manual-device intake to the source-coverage accounting tool. It hashes bytes read from a local source-file descriptor and rejects a mismatch with the request's asserted source hash, recomputes the intake against the bound base model, and maps each admitted source ID to the explicit canonical device and load-port IDs. Incomplete/count-only rows remain unresolved. It returns a detached candidate model and a versioned report; it does not mutate the base or upload anything.

Strict mode refuses unresolved inventoried IDs; it does not prove the manually supplied list contains every item in the file. The file is hashed, not parsed. Neither the hash nor the mapping authenticates the caller, proves that the entered facts came from the source, verifies their type/quantity/location, establishes spatial registration or clearance, or approves an electrical design. Source IDs and model facts may be private. A file or its parent path can change during or after reading, so the digest identifies only the bytes actually read and does not guarantee what that path refers to later. Source files must be nonempty regular files of at most 256 MiB; on platforms supporting `O_NOFOLLOW`, final-component symlinks are refused; symlinks in parent directories may be followed.

The report is bound to the resulting intake candidate. A later model, source or request change requires a new audit. This adapter cannot audit a downstream modified model; use a separate explicit mapping and audit. To verify a saved report, call `validate_manual_intake_coverage` with the current base, request and source file; schema validation alone cannot prove cross-field consistency, freshness or authenticity. The API is opt-in and does not call the router or saved PDF-reviewed workflow. This is partial #241 support, not issue closure or a full takeoff/design integration.

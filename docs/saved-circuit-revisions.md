# Saved revisions with preliminary circuit design

Circuit-enabled saved deliveries retain a local `circuit-inputs/` validation package in the same atomic, hashed publication transaction. It contains the original base-model JSON bytes, original circuit-request JSON bytes, original decision and registration JSON bytes, the admitted canonical snapshot before design, and every cited placement/design evidence document. These are retained inputs and derived snapshots, not a competing model. They may contain customer source material and must stay private wherever customer data is used. This change performs no uploads or remote evidence fetches.

The existing completion marker covers every validation file. The consumer accepts the circuit artifact, stage and required scalar receipt together, and rejects extra files, missing inputs, contradictory receipts or unsupported stage sets. Raw base/request/decision/registration bytes must match their original input receipts. Evidence bytes must match their cited document digests and all available document receipts. The report and artifact must agree on the typed request, exact request fingerprint and admitted snapshot digest.

The verifier reuses the existing placement-assertion materialization core over retained source-review metadata, original decisions/registrations and actual cited evidence bytes. The resulting canonical model must exactly equal the admitted snapshot. It then runs the existing reviewed circuit gate against that snapshot and original base, and requires exact equality with the published final canonical model and design report. This binds graph IDs, geometry, rules, connector choices, confidence and owner-relative provenance to the explicit reviewed decision. Physical limitations, unresolved reasons and the requested inventory group must also agree with the replay.

Source pixels and provider calls are not repeated. Replaying retained metadata does not authenticate a reviewer, provider identity or original source observation. Existing source identity, journal, quantity, scope, confidence, trusted GLB/bundle and IFC checks continue to run. Engineering, capacity, conductor adequacy, fill, supports, buildability and code compliance remain unverified.

Comparison output keeps the existing canonical `build_revision_diff` JSON unchanged. Each enabled side adds `circuit_design_lineage` to its separate context metadata, containing the full request, request fingerprint, admitted snapshot digest, status, deferral reasons and created/inventory IDs. Source-observed, buildability and compliance flags remain false. A newly reviewed height can change route lengths and fittings while logical device, route, circuit and conductor IDs remain stable; those differences are ordinary canonical changes with source and design provenance.

Circuit-disabled saved deliveries and comparison output retain their original format. Historical circuit-enabled deliveries without the retained validation package are refused; they are not retroactively certified. Generate a fresh local version with the explicit inputs when supported verification is required. Changed-source identity reconciliation and pricing remain outside this consumer.

# Explicit manual-device intake (local, opt in)

This boundary turns individually supplied takeoff rows into canonical devices and explicit, unconnected electrical load ports. It accepts only rows with an explicit quantity of one, stable caller-selected device and port IDs, caller-supplied type label, existing level, device and port positions and normalized rotations, port direction, and confidence. Coordinates must already use the model's stated frame, right-handed +Z and metres. No unit conversion, height, offset, rotation, panel, circuit, load, grouping, route or code rule is guessed. Device type labels are not checked against a catalog. The fixed `electrical`/`load` port type describes the requested intake operation and does not assert source observation.

Compute `manual_intake_request_sha256(...)` over the normalized request content, then pass that digest to `admit_manual_devices(...)` with the base model and all of the same fields. The separately supplied `base_model_sha256` must equal `model_fingerprint(base_model)`. A changed model, source hash or normalized request content requires a new digest; row reordering and equivalent integral number forms do not alter it. the caller must review the revised facts before use. The digest does not prove that review occurred. Hashes correlate the submitted facts; they do not authenticate the caller or prove those facts came from the source. The source SHA and coordinate frame are caller assertions, not registration or completeness proof. The stable IDs may be deliberately reused in a new request, but correspondence between revisions is not inferred. The same source hash and item ID cannot be admitted twice into the returned model; a changed source hash does not prove that its rows are different, so the caller must reconcile revisions.

Missing fields or quantity-only rows remain unresolved; malformed values, unknown levels, stale bindings and any canonical ID collision reject the request. The function returns a detached candidate model plus a source-bound report; it never mutates the original model or automatically invokes a router. Source IDs and model facts may be private; no network or file upload occurs. Persist the candidate/report privately if desired and rerun against the unchanged base for deterministic replay.

The result is user-supplied, not source-observed, field-verified, engineered or code-approved. It does not qualify for the existing saved reviewed-electrical pipeline by itself. A separate preliminary routing call requires an explicit panel and source port, explicit load-port mapping, groups, rules and routing controls; that existing router can replace previously managed designs, so inspect its behavior before calling it. This is partial support for #72 and #241, not closure of either.

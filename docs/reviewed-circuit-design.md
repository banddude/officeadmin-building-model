# Reviewed preliminary circuit connections

The optional circuit stage connects admitted placements through the existing canonical routing engine. It does not invent a panel, select arbitrary existing ports, or fill missing physical inputs from prototype defaults. The stage is disabled unless `circuit_design` is supplied to `deliver_reviewed_electrical`.

`ReviewedCircuitRequest.capture(base_model, symbol_review, assertion_review, ...)` binds the request to all three exact snapshots. Supply the existing panelboard ID and electrical source-port ID, explicit ordered circuit groups of proposal IDs, and one `ReviewedLoadPort` for each selected proposal. Each load connector has a caller-selected stable ID, finite canonical-frame offset in metres from the admitted device position, and a nonzero direction. These are designed connector assertions, not measurements from a drawing. Existing source equipment and its port are retained unchanged.

The request requires every field of `CircuitDesignRules` and `RoutingOptions`, including values equal to engine defaults. Missing profiles or fields produce named deferrals; malformed, nonfinite, unsupported, or stale inputs reject the delivery. Rule references identify the caller's design basis and are not independently verified by this stage. Hash-bound, nonempty project-decision bytes with user provenance document the grouping and physical assumptions. No jurisdiction, edition, capacity, or compliance determination is implied.

Missing source equipment, source port, level, admitted placement, load connector, grouping, evidence, or rule references defer the entire request. Existing circuiting and load connectors require reconciliation. An unavailable route returns the admitted model without any partial ports, circuits, conductors, routes, or fittings. Invalid references and identity collisions fail rather than silently substitute another object.

A successful request emits canonical preliminary circuits, conductors, routes and fittings. The report and `circuit_design` artifact retain the complete request and its fingerprint. New graph entities carry design-decision evidence and confidence; the source objects retain their observed provenance. Quantity rows use the explicit `inventory_group`, preserve inferred geometry and user-directed design, and exports derive from this same canonical snapshot. All generated connections remain preliminary: load calculation, source capacity, conductor sizing adequacy, fill, supports, fasteners, engineering verification, and code compliance remain unresolved. `buildable` and compliance claims remain false.

For the saved command, use manifest version `saved-electrical-design-input-v1` and add `circuit_design` as a normal local path/SHA-256 reference to the request JSON (or null to disable). The existing `saved-electrical-input-v1` remains supported without this field. Publication includes `circuit-design.json` in the existing hashed completion transaction. This extension is not yet accepted by consumers that only recognize the original saved-delivery artifact/stage set, including the independently developed saved-revision comparison; those consumers must explicitly add support before comparison.

The synthetic regression draws three distinct marks into PDF bytes, admits two placements and defers the third, supplies a real canonical panel/source port, and chooses an explicit non-default 48 V/PVC/10 AWG profile. Independent rectilinear distances yield 30 m of raceway and 120 m of conductors. A fresh reviewed height change yields 31 m of raceway with stable device and connection identities. The actual saved command, repeatability, completion hashes, IFC identity/provenance, missing-input deferrals, and atomic route failure are exercised without a live provider or customer data.
